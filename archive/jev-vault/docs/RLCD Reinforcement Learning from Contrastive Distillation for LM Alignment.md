###### Abstract

We propose Reinforcement Learning from Contrastive Distillation (RLCD), a method for aligning language models to follow principles expressed in natural language (e.g., to be more harmless) without using human feedback. RLCD creates preference pairs from two contrasting model outputs, one using a positive prompt designed to encourage following the given principles, and one using a negative prompt designed to encourage violating them. Using two different prompts causes model outputs to be more differentiated on average, resulting in cleaner preference labels in the absence of human annotations. We then use the preference pairs to train a preference model, which is in turn used to improve a base unaligned language model via reinforcement learning. Empirically, RLCD outperforms RLAIF ([Bai et al., 2022b](https://arxiv.org/html/2307.12950v3#bib.bib4)) and context distillation ([Huang et al., 2022](https://arxiv.org/html/2307.12950v3#bib.bib10)) baselines across three diverse alignment tasks—harmlessness, helpfulness, and story outline generation—and when using both 7B and 30B model scales for simulating preference data.

## 1 Introduction

Figure 1: Stylized illustration showing RLCD compared to standard RLAIF and context distillation on harmlessness attribute. RLCD generates preference pairs using two contrasting prompts p+,p−p\_{+},p\_{-}, and labels according to the prompt used, thus making use of both pairwise preferences for RL as well as directional attribute change in outputs as encouraged by prompts. RLCD then trains a preference model on the resulting pairs, which is used to guide the LLM alignment via PPO.

Reinforcement Learning from Human Feedback (RLHF) has recently been used to great effect to align pretrained large language models (LLMs) toward desirable behaviors like harmlessness and helpfulness ([Bai et al., 2022a](https://arxiv.org/html/2307.12950v3#bib.bib3)), achieving state-of-the-art results on a variety of tasks ([OpenAI, 2023](https://arxiv.org/html/2307.12950v3#bib.bib19)).

A standard RLHF procedure fine-tunes an initial unaligned LLM using an RL algorithm such as PPO ([Schulman et al., 2017](https://arxiv.org/html/2307.12950v3#bib.bib24)), optimizing the LLM to align with human preferences. RLHF is thus critically dependent on a reward model derived from human-labeled preferences, typically pairwise preferences on LLM outputs (o1,o2)(o\_{1},o\_{2}) generated from a shared prompt pp.

However, collecting human pairwise preference data, especially high-quality data, may be expensive and time consuming at scale. Thus approaches have been proposed to obtain labels without human annotation, such as Reinforcement Learning from AI Feedback (RLAIF) and context distillation.

RLAIF approaches (e.g., [Bai et al. (2022b)](https://arxiv.org/html/2307.12950v3#bib.bib4)) simulate human pairwise preferences by scoring o1o\_{1} and o2o\_{2} with an LLM (Figure [1](https://arxiv.org/html/2307.12950v3#S1.F1 "Figure 1 ‣ 1 Introduction ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment") center); the scoring LLM is often the same as the one used to generate (o1,o2)(o\_{1},o\_{2}). Of course, the resulting LLM pairwise preferences are somewhat noisier than human labels. However, this problem is exacerbated by using the same prompt pp to generate both o1o\_{1} and o2o\_{2}, causing o1o\_{1} and o2o\_{2} to often be of very similar quality and thus hard to differentiate (e.g., Table [1](https://arxiv.org/html/2307.12950v3#S3.T1 "Table 1 ‣ 3.3 Intuitions for RLCD ‣ 3 Reinforcement Learning From Contrastive Distillation ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")). Consequently, training signal can be overwhelmed by label noise, yielding lower-quality preference data.

Meanwhile, context distillation methods (e.g., [Sun et al. (2023)](https://arxiv.org/html/2307.12950v3#bib.bib27)) create more training signal by modifying the initial prompt pp. The modified prompt p+p\_{+} typically contains additional context encouraging a directional attribute change in the output o+o\_{+} (Figure [1](https://arxiv.org/html/2307.12950v3#S1.F1 "Figure 1 ‣ 1 Introduction ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment") right). However, context distillation methods only generate a single output o+o\_{+} per prompt p+p\_{+}, which is then used for supervised fine-tuning, losing the pairwise preferences which help RLHF-style approaches to derive signal from the contrast between outputs. Multiple works have observed that RL approaches using preference models for pairwise preferences can substantially improve over supervised fine-tuning by itself when aligning LLMs ([Ouyang et al., 2022](https://arxiv.org/html/2307.12950v3#bib.bib20); [Dubois et al., 2023](https://arxiv.org/html/2307.12950v3#bib.bib8)).

Therefore, while both RLAIF and context distillation approaches have already been successfully applied in practice to align language models, we posit that it may be even more effective to combine the key advantages of both. That is, we will use RL with pairwise preferences, while also using modified prompts to encourage directional attribute change in outputs.

Concretely, we propose Reinforcement Learning from Contrastive Distillation (RLCD). The core idea is that we can modify not just the process of labeling the preference pairs in RLHF or RLAIF, but also the initial process of generating them from the base model; the two responses in a preference pair do not need to be generated i.i.d. RLCD generates preference data as follows. Rather than producing two i.i.d. (o1,o2)(o\_{1},o\_{2}) from the same prompt pp as in RLAIF, RLCD creates two variations of pp: a positive prompt p+p\_{+} similar to context distillation which encourages directional change toward a desired attribute, and a negative prompt p−p\_{-} which encourages directional change against it (Figure [1](https://arxiv.org/html/2307.12950v3#S1.F1 "Figure 1 ‣ 1 Introduction ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment") left). We then generate model outputs (o+,o−)(o\_{+},o\_{-}) respectively, and automatically label o+o\_{+} as preferred—that is, RLCD automatically “generates” pairwise preference labels by construction. We then follow the standard RL pipeline of training a preference model followed by PPO.

Compared to RLAIF-generated preference pairs (o1,o2)(o\_{1},o\_{2}) from the same input prompt pp, there is typically a clearer difference in the quality of o+o\_{+} and o−o\_{-} generated using RLCD’s directional prompts p+p\_{+} and p−p\_{-}, which may result in less label noise. That is, intuitively, RLCD exchanges having examples be closer to the classification boundary for more accurate labels on average. Compared to standard context distillation methods, on top of leveraging pairwise preferences for RL training, RLCD can derive signal not only from the positive prompt p+p\_{+} which improves output quality, but also from the negative prompt p−p\_{-} which degrades it. Positive outputs o+o\_{+} don’t need to be perfect; they only need to contrast with o−o\_{-} on the desired attribute while otherwise following a similar style.

We evaluate RLCD through both human and automatic evaluations on three tasks, aiming to improve the ability of LLaMA-7B ([Touvron et al., 2023a](https://arxiv.org/html/2307.12950v3#bib.bib29)) to generate harmless outputs, helpful outputs, and high-quality story outlines. As shown in Sec. [4](https://arxiv.org/html/2307.12950v3#S4 "4 Experiments ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment"), RLCD substantially outperforms both RLAIF and context distillation baselines in pairwise comparisons when simulating preference data with LLaMA-7B, while still performing equal or better when simulating with LLaMA-30B. Code and simulated preference data are available at https://github.com/facebookresearch/rlcd.

## 2 Related Work

Lately, several RL approaches leveraging reward models trained on human preferences ([Ouyang et al., 2022](https://arxiv.org/html/2307.12950v3#bib.bib20); [Bai et al., 2022a](https://arxiv.org/html/2307.12950v3#bib.bib3); [Zhu et al., 2023](https://arxiv.org/html/2307.12950v3#bib.bib32); [Rafailov et al., 2023](https://arxiv.org/html/2307.12950v3#bib.bib22)) have been applied to align strong pretrained LLMs ([Stiennon et al., 2020](https://arxiv.org/html/2307.12950v3#bib.bib26); [OpenAI, 2022](https://arxiv.org/html/2307.12950v3#bib.bib18); [OpenAI, 2023](https://arxiv.org/html/2307.12950v3#bib.bib19); [Anthropic, 2023](https://arxiv.org/html/2307.12950v3#bib.bib1); [Touvron et al., 2023b](https://arxiv.org/html/2307.12950v3#bib.bib30)). However, it can be expensive to collect human pairwise preferences.

Reinforcement Learning from AI Feedback. RLAIF simulates human pairwise preferences using a LLM, whether the same LLM to be aligned later ([Bai et al., 2022b](https://arxiv.org/html/2307.12950v3#bib.bib4)) or a stronger LLM as an oracle ([Dubois et al., 2023](https://arxiv.org/html/2307.12950v3#bib.bib8)). Such methods typically obtain pairwise preferences by scoring two i.i.d. outputs (o1,o2)(o\_{1},o\_{2}). RLCD instead generates outputs (o+,o−)(o\_{+},o\_{-}) from different distributions, obviating the need for post hoc scoring (whether human or AI).

Context Distillation. RLCD is related to context distillation approaches, which generate data for supervised fine-tuning by prompting a language model with different contexts ([Askell et al., 2021](https://arxiv.org/html/2307.12950v3#bib.bib2); [Choi et al., 2022](https://arxiv.org/html/2307.12950v3#bib.bib7); [Snell et al., 2022](https://arxiv.org/html/2307.12950v3#bib.bib25); [Huang et al., 2022](https://arxiv.org/html/2307.12950v3#bib.bib10)). In contrast to knowledge distillation approaches using stronger models as a teacher ([Kim & Rush, 2016](https://arxiv.org/html/2307.12950v3#bib.bib11); [Chang et al., 2023](https://arxiv.org/html/2307.12950v3#bib.bib5)), context distillation methods often generate data using the same LLM being aligned or fine-tuned later. In particular, [Sun et al. (2023)](https://arxiv.org/html/2307.12950v3#bib.bib27) apply this approach to align LLaMA-65B ([Touvron et al., 2023a](https://arxiv.org/html/2307.12950v3#bib.bib29)). Unlike existing context distillation approaches, RLCD generates pairwise preference data to train a preference model followed by applying RL. Consequently, RLCD can derive training signal from the contrast in output distributions for two different context-modified prompts p+p\_{+} and p−p\_{-}.

Reinforcement Learning with Contrastive Objective. Using a contrastive loss in RL has proven effective in various scenarios ([Oord et al., 2018](https://arxiv.org/html/2307.12950v3#bib.bib17); [Laskin et al., 2020](https://arxiv.org/html/2307.12950v3#bib.bib12); [Liu et al., 2021](https://arxiv.org/html/2307.12950v3#bib.bib14); [Laskin et al., 2022](https://arxiv.org/html/2307.12950v3#bib.bib13); [Eysenbach et al., 2022](https://arxiv.org/html/2307.12950v3#bib.bib9)). Compared to standard reward signals that may lead to insufficient numerical differences between good and bad cases, contrastive loss naturally focuses on sample pairs with similar appearances but different underlying semantics with current representations ([Tian, 2022](https://arxiv.org/html/2307.12950v3#bib.bib28)), thus improving sample efficiency and model quality. RLCD employs a similar idea to improve the generation of simulated preference data in the RLHF pipeline.

## 3 Reinforcement Learning From Contrastive Distillation

We now describe our method, Reinforcement Learning from Contrastive Distillation (RLCD), a novel method for simulating the initial pairwise preference data in an RLHF pipeline without accessing a stronger “oracle” LLM. Our main innovation is the idea that we can modify the generation procedure of the responses in a preference pair, and do not need to generate them i.i.d.

### 3.1 Method Description

RLCD begins with an initial unaligned LLM and a set of prompts to be used as starting points for pairwise preference data generation, similar to RLHF or RLAIF. For each prompt pp, RLCD then constructs p+p\_{+} and p−p\_{-} (green and orange respectively in Figure [1](https://arxiv.org/html/2307.12950v3#S1.F1 "Figure 1 ‣ 1 Introduction ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")), which should respectively encourage a directional change toward or against the attribute of interest (e.g., harmlessness, helpfulness). We then obtain corresponding outputs o+o\_{+} and o−o\_{-} by feeding p+p\_{+} and p−p\_{-} into the original LLM. When constructing the resulting training pair (o+,o−)(o\_{+},o\_{-}), we automatically label o+o\_{+} as preferred without further post hoc scoring.

After preference training pairs (o+,o−)(o\_{+},o\_{-}) are created, RLCD follows the standard RLHF pipeline by training a preference model on the simulated preferences; this preference model is also based on fine-tuning the same unaligned LLM that we started with. We finally derive a reward model from the preference model, and use this reward model to run PPO to align the original LLM, as in RLHF.

#### 3.1.1 Description of PPO Fine-tuning

For completeness, we briefly summarize the procedure by which we use PPO ([Schulman et al., 2017](https://arxiv.org/html/2307.12950v3#bib.bib24)) to fine-tune the language model once we have finished training the preference model.

First, we need to convert the preference model to a reward model. In practice, the preference model operates by assigning a score to each of the two responses independently, and is trained to optimize the difference between the two scores to match the preference data. These scores can then be directly used as the reward for PPO training downstream ([Bai et al., 2022a](https://arxiv.org/html/2307.12950v3#bib.bib3)).

At each step of PPO, an individual training example begins with an input prompt, similar to those used for preference data generation. The language model generates a response based on the prompt, which is then assigned a reward by the reward model, enabling an update to the language model according to PPO (or any other reinforcement learning algorithm). Following common practice, we also include KL-divergence regularization to prevent the language model from deviating too far from its original distribution over the course of PPO fine-tuning (e.g., to mitigate overfitting to the reward model). For a more complete description, we refer the reader to [Bai et al. (2022a)](https://arxiv.org/html/2307.12950v3#bib.bib3).

### 3.2 Positive and Negative Prompt Construction

From a technical standpoint, implementing RLCD is straightforward if starting from an existing RLAIF workflow. The main choice to make is how to construct RLCD’s positive and negative prompts p+,p−p\_{+},p\_{-} for preference pair generation. We identify two major criteria for prompt construction:

1.  1.
    
    p+p\_{+} should be more likely than p−p\_{-} to produce outputs exemplifying the desired attribute (e.g., harmlessness, helpfulness). Equivalently, p−p\_{-} may explicitly encourage directional change toward the opposite attribute.
    
2.  2.
    
    The surface forms of p+p\_{+} and p−p\_{-} should be as similar as possible, for example as in the RLCD box in Figure [1](https://arxiv.org/html/2307.12950v3#S1.F1 "Figure 1 ‣ 1 Introduction ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment"), where p+p\_{+} and p−p\_{-} differ only in the words “harmless” vs. “harmful.”
    

The first criterion is self-evident. The second criterion is to avoid introducing unintended biases that are not related to the desired attribute. Intuitively, p+p\_{+} and p−p\_{-} induce two different distributions; the first criterion ensures that these two distributions differ by as much as possible in the desired attribute, while the second criterion ensures that they differ by as little as possible on orthogonal axes.

Empirically, we find that RLCD is highly capable at amplifying the contrast in prompts p+p\_{+} and p−p\_{-} when compared to baselines using similar prompts, as shown in our experiments (Sec. [4](https://arxiv.org/html/2307.12950v3#S4 "4 Experiments ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")); see also Appendix [A.1](https://arxiv.org/html/2307.12950v3#A1.SS1 "A.1 Harmlessness ‣ Appendix A Data Generation and Scoring Prompts ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment") for further discussion. Thus when designing p+p\_{+} and p−p\_{-} in practice, we find it may often be more worthwhile to focus on the second criterion compared to the first, for instance by just writing a short description in parentheses to create p+p\_{+} and p−p\_{-} as shown in Figure [1](https://arxiv.org/html/2307.12950v3#S1.F1 "Figure 1 ‣ 1 Introduction ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment") left.

### 3.3 Intuitions for RLCD

We discuss some intuitive reasons why RLCD’s preference data generation may be preferred compared to the most similar prior method, RLAIF. For a more complete theoretical analysis, see Appendix [N](https://arxiv.org/html/2307.12950v3#A14 "Appendix N Theoretical Justification For RLCD ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment").

The main reason is that because RLAIF generates two i.i.d. outputs o1o\_{1} and o2o\_{2}, in many cases there may be little to no difference in the attribute of interest, which can result in a low ‘‘signal-to-noise’’ ratio.<sup>1</sup><sup>1</sup> Analogously, it might be odd to run context distillation by reranking i.i.d. outputs from a generic prompt pp, rather than generating outputs from p+p\_{+}. For instance, in the example shown in Table [1](https://arxiv.org/html/2307.12950v3#S3.T1 "Table 1 ‣ 3.3 Intuitions for RLCD ‣ 3 Reinforcement Learning From Contrastive Distillation ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment"), both RLAIF outputs o1o\_{1} and o2o\_{2} help the human to accomplish an unethical objective, and it is unclear which one should be preferred. However, empirically, o2o\_{2} is preferred by a margin at the 60<sup id="S3.SS3.p2.1.1"><span id="S3.SS3.p2.1.1.1">th</span></sup> percentile of label polarity in our RLAIF data generation when using LLaMA-7B (Sec. [4](https://arxiv.org/html/2307.12950v3#S4 "4 Experiments ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")).

While classification models would typically benefit from training examples close to the decision boundary, the problem in RLAIF is that such examples are not human-labeled and therefore may be extremely noisy; it may even be better to avoid such examples if we cannot accurately label them. Compared to RLAIF, RLCD constructs (o+,o−)(o\_{+},o\_{-}) which are more likely to differ on a specified attribute; the difference is readily apparent in Table [1](https://arxiv.org/html/2307.12950v3#S3.T1 "Table 1 ‣ 3.3 Intuitions for RLCD ‣ 3 Reinforcement Learning From Contrastive Distillation ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment"), where o+o\_{+} is clearly more ethical compared to o−o\_{-}. While RLCD’s outputs can at times be noisy as well, they seem to be on average more differentiated compared to RLAIF’s, resulting in more accurate labels; see Appendix [H](https://arxiv.org/html/2307.12950v3#A8 "Appendix H Simulated Preference Pair Examples ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment") for additional, i.i.d. examples.

Furthermore, compared to RLCD, the post hoc scoring in RLAIF requires both outputs o1o\_{1} and o2o\_{2} to be placed in the context window of the scoring LLM, and thus requires the model to have a longer effective context window. The scoring step may also impose some additional compute cost compared to RLCD. As such, RLCD may be preferable when dealing with longer-form outputs, even when using state-of-the-art LLMs with context windows of tens of thousands of tokens ([OpenAI, 2023](https://arxiv.org/html/2307.12950v3#bib.bib19); [Anthropic, 2023](https://arxiv.org/html/2307.12950v3#bib.bib1); [MosaicML, 2023](https://arxiv.org/html/2307.12950v3#bib.bib16); [Chen et al., 2023](https://arxiv.org/html/2307.12950v3#bib.bib6)), which are both expensive to run and may be poor at attending to certain parts of their context window ([Liu et al., 2023](https://arxiv.org/html/2307.12950v3#bib.bib15)).

## 4 Experiments

Tasks. We evaluate RLCD on three tasks, corresponding to three different sets of prompts:

1.  1.
    
    Harmlessness Prompts. Dialogues frequently containing offensive or otherwise socially unacceptable text. The goal is to generate outputs that are socially acceptable, ethical, and/or inoffensive, even when given such toxic context. As a secondary goal, the outputs should still be helpful and relevant, rather than generic pleasantries like “Thank you!” or “Sorry.”
    
2.  2.
    
    Helpfulness Prompts. Dialogues where the human is typically asking for information or advice. The goal is to generate outputs that are helpful.
    
3.  3.
    
    Outlining Prompts. Dialogues where the human provides a story premise and asks for an outline. The goal is to write a well-formed and interesting story outline for the premise.
    

All prompts are framed as generating the next assistant response at some point in the given human-assistant conversation, as shown in e.g., “Initial Prompts” and “Completions” in Figure [1](https://arxiv.org/html/2307.12950v3#S1.F1 "Figure 1 ‣ 1 Introduction ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment").

Our harmlessness and helpfulness prompt sets are inspired by [Bai et al. (2022a)](https://arxiv.org/html/2307.12950v3#bib.bib3), and we use their training sets to derive the initial prompts for preference data simulation; each training set contains slightly over 40000 conversations.<sup>2</sup><sup>2</sup> It is likely that these initial prompts could also be generated procedurally from a much smaller seed set ([Bai et al., 2022a](https://arxiv.org/html/2307.12950v3#bib.bib3); [Sun et al., 2023](https://arxiv.org/html/2307.12950v3#bib.bib27)), although we do not empirically investigate this possibility in this work. We also include the outlining prompt set because we believe it may have higher requirements on long-range planning, in addition to simultaneously composing multiple different attributes (e.g., interestingness, well-formedness, relevance to the premise). For the outlining prompts we use 40000 existing premises from the internet mainly ranging from 10 to 40 tokens in length, and assistant responses automatically start with “Here is a possible outline:\\n\\n1.” to encourage correct basic formatting regardless of which method is being evaluated.

RLCD Positive and Negative Prompts. For the harmlessness task, we write 16 pairs of context phrases for constructing p+p\_{+} and p−p\_{-} (sampling a random pair for each use); these pairs are written to be similar to the 16 scoring prompts used in [Bai et al. (2022b)](https://arxiv.org/html/2307.12950v3#bib.bib4), who implement RLAIF for harmlessness. For helpfulness, we use a single phrase pair, for helpful or unhelpful responses respectively. For outlining, we use three pairs, contrasting interestingness, well-formedness, and premise relevance.

For harmlessness and helpfulness, we create training signal while roughly matching the surface forms of p+p\_{+} and p−p\_{-} by simply placing contrasting descriptions in parentheses before the colon in “Assistant:” indicators, as shown for example in Figure [1](https://arxiv.org/html/2307.12950v3#S1.F1 "Figure 1 ‣ 1 Introduction ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment"). In the outlining task, we match surface forms by ending all prompts with “1.” to indicate the beginning of a numbered outline. All prompts are zero-shot. See Appendix [A](https://arxiv.org/html/2307.12950v3#A1 "Appendix A Data Generation and Scoring Prompts ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment") for full details on preference data simulation prompt formats.

RLCD Implementation and Hyperparameters. For each task we run two variations of RLCD—RLCD<sub id="S4.p7.1.2"><span id="S4.p7.1.2.1">7B</span></sub> and RLCD<sub id="S4.p7.1.3"><span id="S4.p7.1.3.1">30B</span></sub>\---which simulate preference data using the base (pretrained, unaligned) LLaMA-7B and LLaMA-30B respectively. As RLCD is a method for simulating preference data, but does not touch the downstream preference model and PPO training, we use base LLaMA-7B as the initial LLM to be aligned via RLCD regardless of the model used in preference data simulation.<sup>3</sup><sup>3</sup> Alternatively, simulating preference data with LLaMA-30B while aligning LLaMA-7B downstream can be viewed as model distillation, i.e., we are comparing RLCD to baselines on model distillation effectiveness.

Our implementation is based on the AlpacaFarm codebase ([Dubois et al., 2023](https://arxiv.org/html/2307.12950v3#bib.bib8)). We optimize the training parameters for PPO, in particular the number of training steps and KL-regularization term. We otherwise use AlpacaFarm’s default hyperparameters for PPO and for supervised fine-tuning; see Appendix [E](https://arxiv.org/html/2307.12950v3#A5 "Appendix E Implementation Details and Hyperparameters ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment") for full details on hyperparameters.

Baselines. We compare RLCD to three baselines:

1.  1.
    
    LLaMA, i.e., just directly generating outputs using the base unaligned LLaMA-7B (the same initial LLM to be aligned by RLCD and other baselines), included as a sanity check.
    
2.  2.
    
    RLAIF, following Constitutional AI ([Bai et al., 2022b](https://arxiv.org/html/2307.12950v3#bib.bib4)). Since their code and models are non-public, we re-implement using AlpacaFarm. We use the exact same prompt templates as [Bai et al. (2022b)](https://arxiv.org/html/2307.12950v3#bib.bib4) for harmlessness scoring, although we use zero-shot prompting to match RLCD. For helpfulness and outlining scoring, we use prompts written to have similar meaning to those used for generation in RLCD (Appendix [A](https://arxiv.org/html/2307.12950v3#A1 "Appendix A Data Generation and Scoring Prompts ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")).
    
3.  3.
    
    Context-Dist, a context distillation baseline which conducts supervised fine-tuning on only the outputs o+o\_{+} from the same positive prompts p+p\_{+} as used in RLCD.
    

As with RLCD, we experiment with simulating preference data using both LLaMA-7B and LLaMA-30B for RLAIF and Context-Dist (again denoted by subscripts, e.g., RLAIF<sub id="S4.p11.1.1"><span id="S4.p11.1.1.1">7B</span></sub>), though the base model to be aligned remains LLaMA-7B in all cases.

Metrics. For each task, we run pairwise evaluations for RLCD compared to each baseline. As the harmlessness prompts from [Bai et al. (2022b)](https://arxiv.org/html/2307.12950v3#bib.bib4)—while focusing primarily on harmlessness—additionally encourage helpfulness to some degree (Appendix [A.1](https://arxiv.org/html/2307.12950v3#A1.SS1 "A.1 Harmlessness ‣ Appendix A Data Generation and Scoring Prompts ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")), we measure both harmlessness (Harm) and helpfulness (Help) for the harmlessness task.<sup>4</sup><sup>4</sup> See Appendix [D](https://arxiv.org/html/2307.12950v3#A4 "Appendix D Focused Harmlessness Experiments ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment") for a version of the harmlessness task which focuses more exclusively on harmlessness. For the helpfulness and outlining tasks we collect just one set of labels for overall helpfulness (Help) and outline quality (Qual) respectively.

Table 2: Human comparison results for RLCD against each baseline, evaluating harmlessness and helpfulness on harmlessness prompt set; helpfulness on helpfulness prompt set; and outline quality on story outlining prompt set. ## 5 Analysis

We run two additional analyses to provide further insight into RLCD.

### 5.1 Preference Model Evaluation

For the harmlessness and helpfulness tasks, we evaluate RLCD’s preference model compared to RLAIF’s on 2000 gold human-labeled preference data examples from [Bai et al. (2022a)](https://arxiv.org/html/2307.12950v3#bib.bib3), based on the same prompts as used for preference data simulation. We check average binary prediction accuracy (i.e., whether the gold human-preferred output is assigned higher preference probability) as well as the average probability that each preference model assigns to the gold output.

Table 5: Average binary accuracy and probability for favoring gold human-preferred output on harmlessness and helpfulness data, for RLAIF and RLCD preference models. RLCD’s preference models perform better on both datasets.

As shown in Table [5](https://arxiv.org/html/2307.12950v3#S5.T5 "Table 5 ‣ 5.1 Preference Model Evaluation ‣ 5 Analysis ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment"), RLCD’s preference models exhibit higher agreement with human preferences compared to RLAIF’s, whether measured by binary accuracy or by probability of agreement.

Perhaps surprisingly, RLAIF’s harmlessness preference models actually perform worse than chance, even for RLAIF<sub id="S5.SS1.p3.1.1"><span id="S5.SS1.p3.1.1.1">30B</span></sub>, even though RLAIF<sub id="S5.SS1.p3.1.2"><span id="S5.SS1.p3.1.2.1">30B</span></sub> performs quite reasonably downstream for mitigating harmful outputs (e.g., examples in Appendix [I](https://arxiv.org/html/2307.12950v3#A9 "Appendix I Example Outputs ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")).<sup>6</sup><sup>6</sup> On the other hand, RLAIF<sub id="footnote6.1"><span id="footnote6.1.1">7B</span></sub>’s downstream performance is quite poor, more closely reflecting its preference model’s low agreement with humans. In fact, this low agreement may not be entirely unexpected, as [Bai et al. (2022b)](https://arxiv.org/html/2307.12950v3#bib.bib4) also observe that both (1) few-shot prompting for the scoring LLM and (2) well over 10B model scale seem necessary for RLAIF’s preference model to achieve higher than chance agreement with humans on harmlessness. It is also not impossible for RLAIF<sub id="S5.SS1.p3.1.3"><span id="S5.SS1.p3.1.3.1">30B</span></sub> to successfully mitigate harm downstream despite low preference model agreement with humans, as human labels may also contain errors or biases. See Appendix [C](https://arxiv.org/html/2307.12950v3#A3 "Appendix C Few-Shot RLAIF Harmlessness Experiments ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment") for further discussion, as well as experiments with a version of RLAIF using few-shot prompts for scoring.

In any case, RLCD’s learned preference models do not exhibit the same lower-than-chance human agreement as RLAIF’s on the harmlessness prompts. Moreover, RLCD’s preference models exhibit higher agreement with humans compared to RLAIF’s on the helpfulness prompts as well. Even if the preference model’s level of human agreement may not correlate perfectly to downstream performance, we suppose that high human agreement should be somewhat desirable in and of itself.

Finally, RLCD’s preference models make judgments with higher polarity compared to RLAIF’s, likely due to our use of discrete binary preference labels as opposed to continuous probabilities (Figure [1](https://arxiv.org/html/2307.12950v3#S1.F1 "Figure 1 ‣ 1 Introduction ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")). We explore a version of RLAIF that also uses binary preference labels in Appendix [B](https://arxiv.org/html/2307.12950v3#A2 "Appendix B Binarized RLAIF7B Experiments ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment").

### 5.2 Rescoring Variant of RLCD

We additionally investigate a variant of RLCD, RLCD-Rescore, in which we generate preference data (o+,o−)(o\_{+},o\_{-}) using our prompts p+,p−p\_{+},p\_{-} but re-label using the same scoring prompts as in RLAIF. We compare pairwise against RLCD on all three tasks using GPT-4.

Table 6: Percentage of outputs preferred in GPT-4 pairwise comparisons for RLCD vs. RLCD-Rescore variant (re-labeling outputs using RLAIF scoring prompts). RLCD dramatically outperforms RLCD-Rescore at 7B scale for preference data simulation, but rescoring becomes a viable alternative at 30B scale.

As shown in Table [6](https://arxiv.org/html/2307.12950v3#S5.T6 "Table 6 ‣ 5.2 Rescoring Variant of RLCD ‣ 5 Analysis ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment"), RLCD substantially outperforms RLCD-Rescore at 7B model scale for preference data simulation, indicating that labeling o+,o−o\_{+},o\_{-} based on the initial prompts p+,p−p\_{+},p\_{-} used for output generation is much more effective compared to the post hoc rescoring used in RLAIF. At least in the settings we examine, LLaMA-7B appears to be more capable of generating contrasting outputs o+,o−o\_{+},o\_{-} than labeling them after the fact.

However, rescoring becomes a viable alternative at 30B scale, as the scoring LLM becomes more capable of labeling examples closer to the boundary. At such model scales, it may also be possible to run a version of RLCD that mixes labels from the two options (RLCD and RLCD-Rescore), or to use a method such as PREADD ([Pei et al., 2023](https://arxiv.org/html/2307.12950v3#bib.bib21)) to modulate the control strength of the prompts p+,p−p\_{+},p\_{-} to obtain accurately labeled preference pairs closer to the classification boundary. On the other hand, it may also be the case that the larger effective context window requirement for post hoc labeling (Sec. [3.3](https://arxiv.org/html/2307.12950v3#S3.SS3 "3.3 Intuitions for RLCD ‣ 3 Reinforcement Learning From Contrastive Distillation ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")) could cause RLCD-Rescore’s performance to degrade compared to RLCD when o+,o−o\_{+},o\_{-} are much longer than in our current experiments, even when using LLaMA-30B.

## 6 Discussion

In this work we have presented RLCD, a method for aligning LLMs using simulated pairwise preference data obtained from prompting the same LLM. Based on the fundamental idea that we can improve the preference data simulation by not generating response pairs i.i.d., RLCD follows a similar pipeline to RLAIF while adding ideas reminiscent of context distillation. In particular, we simulate pairwise preference data using a positive prompt p+p\_{+} and a negative prompt p−p\_{-}, aiming to amplify the difference between outputs o+,o−o\_{+},o\_{-} by encouraging opposite-directional changes on a desired attribute such as harmlessness. Empirical results on three diverse alignment tasks across multiple model scales for preference data simulation confirm our intuitions that RLCD can be highly effective, outperforming both RLAIF and context distillation baselines. Especially at 7B model scale—where we find that RLAIF performs very poorly—RLCD already works quite decently, potentially enabling researchers and practitioners to experiment with RLAIF-style pipelines much faster and at lower cost.

However, despite our strong empirical results, we think that RLCD only scratches the surface of what is possible for automatic preference data simulation in RLHF pipelines. For instance, across the several experimental settings in this work, our current RLCD approach benefits from intuitively pushing o+o\_{+} and o−o\_{-} farther apart to reduce label noise. In cases where reranking outputs post hoc is easy, or where one has a sufficiently strong scoring LLM to provide accurate labels even close to the classification boundary, one could alternatively attempt to create harder training examples by intentionally pushing o+o\_{+} and o−o\_{-} closer together compared to whatever RLAIF achieves by random chance. Additionally, it could prove useful to simulate preference labels in formats other than a single binary label, such as by ranking more than two outputs at a time or using more fine-grained annotations on longer outputs, and we are excited to investigate these and other possibilities for continuing to improve automatic data simulation procedures for LLM alignment.

## Ethics

Strong general-purpose methods for improving and controlling language models pose a risk of dual use. In this work, we focus on the harmlessness and helpfulness tasks from [Bai et al. (2022a)](https://arxiv.org/html/2307.12950v3#bib.bib3); [Bai et al. (2022b)](https://arxiv.org/html/2307.12950v3#bib.bib4); advancements on the harmlessness task especially have significant potential to mitigate risks associated with deploying strong language models. Our story outline task, based on creative writing, is also relatively innocuous.

Additionally, our experiments in this work are solely in English, and performance could be worse in lower-resource languages.

## Limitations

While we have carefully investigated the effectiveness of RLCD compared to several baselines on three tasks for LLaMA-7B, and even run experiments with preference data simulation using LLaMA-30B, state-of-the-art pretrained LLMs are still much larger, and we have not yet empirically verified our conclusions when aligning larger pretrained LLMs. It would also be interesting to test other algorithms for leveraging preference data such as DPO ([Rafailov et al., 2023](https://arxiv.org/html/2307.12950v3#bib.bib22)).

The performance of both RLCD and baselines also depends on the prompts used for pairwise preference data generation and scoring, so the results could change with different prompts. While it is difficult to entirely eliminate the impact of prompt design on performance, we have attempted to limit this impact in our pairwise comparison experiments by matching the prompt contexts used in RLCD and baselines where possible (Appendix [A](https://arxiv.org/html/2307.12950v3#A1 "Appendix A Data Generation and Scoring Prompts ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")). We use prompts with similar meanings for RLCD and RLAIF, and use the same p+p\_{+} for context distillation as in RLCD. We also use zero-shot prompting throughout our experiments to avoid any influence from few-shot examples.

For RLCD, for each example when simulating data, we randomly sample a pair of descriptions from Table [9](https://arxiv.org/html/2307.12950v3#A1.T9 "Table 9 ‣ A.1 Harmlessness ‣ Appendix A Data Generation and Scoring Prompts ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment") to use when building p+p\_{+} and p−p\_{-}. The pairs correspond directly to the RLAIF prompts in Table [7](https://arxiv.org/html/2307.12950v3#A1.T7 "Table 7 ‣ A.1 Harmlessness ‣ Appendix A Data Generation and Scoring Prompts ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment"). p+p\_{+} and p−p\_{-} are then constructed by placing a description in parentheses before the final colon in the ending “Assistant:” indicator, as shown in the stylized example in Figure [1](https://arxiv.org/html/2307.12950v3#S1.F1 "Figure 1 ‣ 1 Introduction ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment"). We additionally modify previous “Assistant:” strings in the prompt to include the opposite description (i.e., p+p\_{+} ends with “Assistant (helpful, honest inoffensive response):” but previous occurrences of “Assistant:” are replaced with “Assistant (unhelpful, dishonest, toxic response):”), in order to increase contrast between o+o\_{+} and o−o\_{-}.

Compared to RLAIF, RLCD’s prompts are typically shorter and less detailed, as we observed in preliminary experiments that RLCD was able to pick up on much smaller prompting hints compared to RLAIF. For example, we removed many mentions of politeness in the prompts, as we noticed that RLCD otherwise swiftly discovers that prefacing most responses with “Thank you” or “Sorry” is an easy way to improve reward (although doing so does indeed trivially improve harmlessness, we opted for an intuitively “fairer” comparison to RLAIF). We envision that schemes such as PREADD ([Pei et al., 2023](https://arxiv.org/html/2307.12950v3#bib.bib21)) could be an effective way to modulate the strength of different prompting hints in RLCD’s data generation if desired, although we did not explore such methods in this work as RLCD is still highly effective without them.

## Appendix C Few-Shot RLAIF Harmlessness Experiments

Further Discussion of RLAIF Preference Model Human Agreement. First, some further discussion of possible reasons for RLAIF’s preference model exhibiting lower-than-chance agreement with humans on the harmlessness prompts (Table [5](https://arxiv.org/html/2307.12950v3#S5.T5 "Table 5 ‣ 5.1 Preference Model Evaluation ‣ 5 Analysis ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")). One possible cause for low agreement is that the harmlessness scoring prompts (following [Bai et al. (2022b)](https://arxiv.org/html/2307.12950v3#bib.bib4)) encourage helpfulness to some degree as well (Appendix [A.1](https://arxiv.org/html/2307.12950v3#A1.SS1 "A.1 Harmlessness ‣ Appendix A Data Generation and Scoring Prompts ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")), which may at times be at odds with harmlessness ([Bai et al., 2022a](https://arxiv.org/html/2307.12950v3#bib.bib3)). Another factor which may particularly hurt RLAIF<sub id="A3.p1.1.2"><span id="A3.p1.1.2.1">7B</span></sub> is that asking smaller pretrained models e.g., which output is “less harmful” may sometimes result in preferring the worse output simply due to seeing the word “harmful,” as if modeling a bag of words; similar phenomena have been observed in e.g., [Welbl et al. (2021)](https://arxiv.org/html/2307.12950v3#bib.bib31); [Pei et al. (2023)](https://arxiv.org/html/2307.12950v3#bib.bib21). In fact, Figure 12 in [Bai et al. (2022b)](https://arxiv.org/html/2307.12950v3#bib.bib4) suggests that for RLAIF to label harmlessness data with above-chance agreement with humans, we require both: (1) few-shot prompting when scoring, and (2) well over 10B model scale. (Although [Bai et al. (2022b)](https://arxiv.org/html/2307.12950v3#bib.bib4) observed very close to chance performance instead of clearly lower than chance, the evaluation set used in [Bai et al. (2022b)](https://arxiv.org/html/2307.12950v3#bib.bib4) is arguably easier to classify than ours, as they only consider examples that are human-labeled as maximum or minimum harmfulness on a 1-5 Likert scale. They also used a different pretrained LM compared to our experiments.) However, RLAIF<sub id="A3.p1.1.3"><span id="A3.p1.1.3.1">30B</span></sub> still achieves reasonable downstream performance for mitigating harmfulness (e.g., examples in Appendix [I](https://arxiv.org/html/2307.12950v3#A9 "Appendix I Example Outputs ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")) despite its preference model showing lower human agreement; there may be some errors or biases in human labels as well, possibly induced by the prompts or questions being asked during human labeling. On the other hand, we observed that RLAIF<sub id="A3.p1.1.4"><span id="A3.p1.1.4.1">7B</span></sub> seemed fairly ineffective in practice qualitatively, perhaps reflecting the poor agreement of its preference model with human preferences.

RLAIF Few-Shot Experiments. Here, we experiment with RLAIF in a few-shot setting in the harmlessness task, using the same few-shot prompts as in [Bai et al. (2022b)](https://arxiv.org/html/2307.12950v3#bib.bib4) as provided in https://github.com/anthropics/ConstitutionalHarmlessnessPaper. Table [15](https://arxiv.org/html/2307.12950v3#A3.T15 "Table 15 ‣ Appendix C Few-Shot RLAIF Harmlessness Experiments ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment") shows the preference model’s agreement with humans; we corroborate [Bai et al. (2022b)](https://arxiv.org/html/2307.12950v3#bib.bib4)’s findings that few-shot prompting together with larger model scale can yield a preference model with higher than chance agreement with humans.

Table [16](https://arxiv.org/html/2307.12950v3#A3.T16 "Table 16 ‣ Appendix C Few-Shot RLAIF Harmlessness Experiments ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment") shows the final pairwise comparison results against RLCD. The comparison is somewhat unfair to RLCD because RLCD only uses zero-shot prompts. Even so, RLCD<sub id="A3.p3.1.1"><span id="A3.p3.1.1.1">7B</span></sub> still greatly outperforms RLAIF-Few<sub id="A3.p3.1.2"><span id="A3.p3.1.2.1">7B</span></sub>, while RLCD<sub id="A3.p3.1.3"><span id="A3.p3.1.3.1">30B</span></sub> is considered somewhat less harmless compared to RLAIF-Few<sub id="A3.p3.1.4"><span id="A3.p3.1.4.1">30B</span></sub> but is more helpful by a similar margin. ## Appendix E Implementation Details and Hyperparameters

Sampling (and scoring for RLAIF) during preference data simulation uses LLaMA-7B or LLaMA-30B loaded in 8-bit precision with temperature 1. For harmlessness and helpfulness we require “Human” to appear to indicate the end of the assistant response, and additionally ensure that it ends with “\\n” or “</s>.” We further truncate based on appearances of the string “Assistant” which also seem to indicate LLaMA starting a new response. We re-sample responses up to 5 times as needed, otherwise that conversation data point is skipped (very rare). Since formatting in the outline task is more difficult, we are slightly more lenient: if the string “Human” to indicate the end of the assistant response is not present, we split by newlines and then truncate lines from the end until removing the last line that starts with a number, with the assumption that lines starting with numbers correspond to items in the outline.

For RLCD and all baselines we use the default hyperparameters from AlpacaFarm ([Dubois et al., 2023](https://arxiv.org/html/2307.12950v3#bib.bib8)) for supervised fine-tuning, preference model training, and PPO, except that for the PPO training we optimize over the KL coefficient and the number of PPO “steps” (corresponding to 512 rollouts per step)—similar to [Dubois et al. (2023)](https://arxiv.org/html/2307.12950v3#bib.bib8), we observed that performance would degrade somewhat if we used too many PPO steps. Therefore, for both RLAIF and RLCD for all three tasks, we selected KL coefficients from among {0.001,0.002,0.004,0.008,0.016,0.032}\\{0.001,0.002,0.004,0.008,0.016,0.032\\} and a number of PPO steps from among {20,40,60,80}\\{20,40,60,80\\} using a grid search, with the exception of the outlining task where we fixed 20 PPO steps due to observing earlier performance degradation (for example, mode collapse) for both methods. We do not assume access to a stronger evaluation model when optimizing hyperparameters; therefore, RLCD’s hyperparameters are selected by generating 1000 model outputs on validation set prompts for each hyperparameter configuration, followed by evaluating average reward according to RLCD’s own learned reward model. RLAIF evaluates similarly with its own learned reward model.

We parse GPT-4’s output as follows, using simple heuristics based on inspecting several outputs. If the output starts with “(A),” “(B),” “Response (A),” or “Response (B),” we mark the corresponding response as preferred; this covers the vast majority of cases. In some remaining cases GPT-4 will initially refuse to give a straight answer, but say something like “However, (A) may be slightly better than (B) on some axis”; therefore, we additionally parse any text after the token “However”, remove any instances of “than (A)” or “than (B)”, and then label the corresponding response preferred if exactly one of “(A)” or “(B)” remains in the resulting string. If we still fail to parse an answer, we give both responses a 0.5 score rather than a binary 0 or 1. The vast majority of such parsing failures are due to GPT-4 legitimately either giving no preference or refusing to answer. The latter case is most common in the presence of offensive context in our evaluations on the harmlessness test set; parsing failures are rarer on the helpfulness and outlining test sets.

For both methods, there is of course substantial noise in the quality of outputs due to using pretrained LLaMA-7B or LLaMA-30B for data generation, but in many cases o+o\_{+} is noticeably better than o−o\_{-} even in just these few examples. Meanwhile, the labels for RLAIF seem to be noisier on average in most cases; LLaMA-7B also may have some positioning bias toward the second example.

## Appendix J Additional Automatic Metrics for Model Outputs

We run several additional automatic metrics to check RLCD’s empirical effectiveness compared to baselines.

### J.1 Evaluation With Held-out Reward Model

Although we didn’t use any human preference data for our main experiments, the harmlessness and helpfulness datasets from which we source our prompts did originally come with human preference pairs. Here we train a held-out reward model based on LLaMA-7B using that preference data, following the same procedure by which we train the reward models for RLAIF and RLCD in our main experiments. The held-out reward model isn’t perfect for our purposes, as the instructions for human labeling may not correspond exactly to our prompts for RLAIF or RLCD. Nevertheless, when we use that reward model to evaluate the final outputs of different methods from our main experiments, we still observe that RLCD’s outputs achieve the highest reward in all cases except for on helpfulness at 30B scale, where the reward is slightly lower than RLAIF’s. ## Appendix K Automatic Metrics For Simulated Preference Data

### K.1 Label Correctness According to Held-Out Model

## Appendix N Theoretical Justification For RLCD

We present some additional theoretical motivation for RLCD, showing that in a simplified setup, RLCD’s labels are not only more likely to be correct compared to RLAIF in an overall sense, but also may be more likely to be correct on “hard” examples with appropriate selection of the positive and negative prompts p+p\_{+} and p−p\_{-}.

Setup. Say our attribute of interest (e.g., harmlessness) can be quantified on a real-valued axis, and that we’re just predicting binary preference labels rather than probabilities. We will denote our initial generative model (e.g., base LLaMA) as 𝒢⁡(output|prompt)\\mathcal{G}(\\mathrm{output}|\\mathrm{prompt}), or 𝒢⁡(o|p)\\mathcal{G}(o|p). Say A⁡(o)A(o) is an unknown function denoting the true value of the attribute, i.e. the ground truth preference label for a pair (o1,o2)(o\_{1},o\_{2}) should be o1o\_{1} preferred over o2o\_{2} if A⁡(o1)\>A⁡(o2)A(o\_{1})>A(o\_{2}). Lastly, say we also have a model 𝒟⁡(o1,o2)\\mathcal{D}(o\_{1},o\_{2}) which (noisily) predicts the preference label, e.g., using the RLAIF scoring prompts with base LLaMA.

Simplifying Assumptions. Suppose that 𝒢⁡(o|p)\\mathcal{G}(o|p) generates oo according to a distribution such that A⁡(o)∼N⁡(μ⁡(p),σ𝒢)A(o)\\sim N(\\mu(p),\\sigma\_{\\mathcal{G}}), noting μ\\mu depends on pp. (One can think of this μ⁡(p)\\mu(p) as the “attribute value” of the prompt pp. The exact distribution is not critical, as long as it has a roughly similar shape, e.g., unimodal.) Suppose that 𝒟⁡(o1,o2)\\mathcal{D}(o\_{1},o\_{2}) predicts preference labels according to the sign of \[A⁡(o1)+e1\]−\[A⁡(o2)+e2\]\[A(o\_{1})+e\_{1}\]-\[A(o\_{2})+e\_{2}\], where e1e\_{1} and e2e\_{2} are error terms i.i.d. according to e∼N⁡(0,σ𝒟)e\\sim N(0,\\sigma\_{\\mathcal{D}}). For simplicity we’ll also assume σ𝒢\=σ𝒟\=1\\sigma\_{\\mathcal{G}}=\\sigma\_{\\mathcal{D}}=1, noting both 𝒢\\mathcal{G} and 𝒟\\mathcal{D} are based on the same LLaMA in practice. (There’s some reason to think σ𝒟\\sigma\_{\\mathcal{D}} may even be larger than σG\\sigma\_{G} at smaller model scales due to the RLAIF scoring prompts operating over longer contexts, as they need to fit both outputs in the context.)

Analysis. With RLAIF under our simplifying assumptions, we can determine the true probability of getting a correctly labeled pair (o1,o2)(o\_{1},o\_{2}) with oi∼𝒢⁡(o|p)o\_{i}\\sim\\mathcal{G}(o|p) and labeling according to 𝒟\\mathcal{D}. This probability works out to 0.750.75 in our setting with σ𝒢\=σ𝒟\=1\\sigma\_{\\mathcal{G}}=\\sigma\_{\\mathcal{D}}=1, though it will naturally be higher or lower depending on how large σ𝒟\\sigma\_{\\mathcal{D}} actually is compared to σ𝒢\\sigma\_{\\mathcal{G}} in practice.<sup>7</sup><sup>7</sup> 0.750.75 is actually higher than the agreement with humans of either RLAIF’s or RLCD’s labels in practice (Appendix [K.1](https://arxiv.org/html/2307.12950v3#A11.SS1 "K.1 Label Correctness According to Held-Out Model ‣ Appendix K Automatic Metrics For Simulated Preference Data ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")), supporting the idea that σD\\sigma\_{D} is indeed quite nontrivial in practice. However, for the “hard” examples where the true attribute values A⁡(o1)A(o\_{1}) and A⁡(o2)A(o\_{2}) are very close, the probability of labeling correctly will be very close to 0.50.5 due to adding the error terms in 𝒟\\mathcal{D}. For example, if we filter our generated examples to the “hard” examples where A⁡(o1)A(o\_{1}) and A⁡(o2)A(o\_{2}) differ by at most 0.20.2, we see that the probability of correct labels is only roughly 0.5280.528 under simulation in 10810^{8} trials.

Meanwhile, if we select RLCD’s p+p\_{+} and p−p\_{-} such that the difference between μ⁡(p+)\\mu(p\_{+}) and μ⁡(p−)\\mu(p\_{-}) is very large, the fraction of correct preference labels can be arbitrarily close to 11, at the cost of making the examples very easy for downstream training. In practice we strike a middle ground where μ⁡(p+)\\mu(p\_{+}) and μ⁡(p−)\\mu(p\_{-}) are clearly different, so the fraction of correct labels is higher, but still far from 11 (Appendix [K.1](https://arxiv.org/html/2307.12950v3#A11.SS1 "K.1 Label Correctness According to Held-Out Model ‣ Appendix K Automatic Metrics For Simulated Preference Data ‣ RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment")).

However, recall that RLCD labels pairs not based on 𝒟\\mathcal{D}, but simply based on which prompt was used to generate which output. For example, if μ⁡(p+)−μ⁡(p−)\=0\\mu(p\_{+})-\\mu(p\_{-})=0 then the label accuracy will be only 0.50.5. What’s interesting is that for larger values of μ⁡(p+)−μ⁡(p−)\\mu(p\_{+})-\\mu(p\_{-}), while there will be fewer hard examples, we can actually get a higher label accuracy on hard examples—even conditioned on A⁡(o+)A(o\_{+}) and A⁡(o−)A(o\_{-}) being close, it is more likely for A⁡(o+)\>A⁡(o−)A(o\_{+})>A(o\_{-}) than vice versa. For example, if we set μ⁡(p+)−μ⁡(p−)\=3\\mu(p\_{+})-\\mu(p\_{-})=3, then we get 0.5740.574 accuracy on examples where A⁡(o+)A(o\_{+}) and A⁡(o−)A(o\_{-}) differ by at most 0.20.2, again simulating over 10810^{8} trials. (Note that this analysis can also explain why the RLCD-Rescore variation, which relabels RLCD’s o+o\_{+} and o−o\_{-} using 𝒟\\mathcal{D}, also performs poorly compared to RLCD at 7B scale.)

Additional Takeaways. Our analysis also suggests improvements to how one might scale RLCD to larger models. For RLCD, we would like to choose μ⁡(p+)−μ⁡(p−)\\mu(p\_{+})-\\mu(p\_{-}) sufficiently large so that we get higher label accuracy (including for hard examples) but not so large that all the examples become trivial to label. Since we’d expect both σ𝒢\\sigma\_{\\mathcal{G}} and σ𝒟\\sigma\_{\\mathcal{D}} to perhaps decrease compared to smaller models, if we want to keep similar distributional properties at larger model scales then we should decrease μ⁡(p+)−μ⁡(p−)\\mu(p\_{+})-\\mu(p\_{-}). Therefore, while in our current implementation of RLCD<sub id="A14.p7.1.2"><span id="A14.p7.1.2.1">30B</span></sub> we just use the same p+p\_{+} and p−p\_{-} as for RLCD<sub id="A14.p7.1.3"><span id="A14.p7.1.3.1">7B</span></sub>, it may be better to make the directional attribute encouragement “weaker” in the prompts at larger model scales, to decrease μ⁡(p+)−μ⁡(p−)\\mu(p\_{+})-\\mu(p\_{-}). This would be a very interesting direction for further exploration.
